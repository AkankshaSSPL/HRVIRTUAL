## What was fixed in this session (2026-07-28)

### Fix 1 — Agent onboarding multi-turn conversation was completely broken

**File:** `backend/app/agents/coordinator_agent/service.py` (~line 208)

**The bug:** After turn 1 ("onboard Priya as developer"), the agent creates the employee and asks for email. User types "priya@company.com". The coordinator's NL extractor sees no employee name in that message → sets `missing_fields = ["employee_name"]`. The coordinator's gate on line 208 said:

```python
if extraction.missing_fields or (extraction.confidence < threshold and not fallback_is_meaningful):
    return clarification
```

The `OR` meant `missing_fields` alone was enough to hit clarification — even though `_analyze_intent()` (called just above) had already identified an active onboarding conversation via `_has_active_onboarding_finishing()`. The user's reply went nowhere. Onboarding was permanently stuck after turn 1.

**The fix:** One line added — detect when `_analyze_intent` has already resolved the message as an onboarding continuation and skip the gate:

```python
is_onboarding_continuation = fallback_route.get("matched_intent") == "onboarding finishing conversation"
if not is_onboarding_continuation and (extraction.missing_fields or ...):
```

**How the continuation detection works:** Every response from `OnboardingAgent` returns `structured_response.type = "onboarding_finishing"`. `_has_active_onboarding_finishing()` scans the last 8 `AgentRun` rows for the current user and returns True if any has that type and `completed = false`. When True, `_analyze_intent` returns `matched_intent = "onboarding finishing conversation"` and our guard bypasses the missing_fields check.

### Fix 2 — Employment type "intern" / "contract" / "part time" crashed silently

**File:** `backend/app/agents/employee_agent/tools.py` (~line 436)

**The bug:** The `EmploymentType` enum only has `FULL_TIME` and `CONSULTANT`. `_parse_employment_type()` did:
```python
return EmploymentType(normalized)   # raises ValueError for anything else
```

User says "onboard Raj as intern" → LLM extracts `employment_type = "intern"` → `_parse_employment_type("intern")` → `ValueError` → coordinator catches it and returns a generic error banner.

**The fix:** Try/except with a fallback map:
```python
_EMPLOYMENT_TYPE_MAP = {
    "PART_TIME": EmploymentType.FULL_TIME,
    "CONTRACT": EmploymentType.CONSULTANT,
    "FREELANCE": EmploymentType.CONSULTANT,
    "INTERN": EmploymentType.FULL_TIME,
    "INTERNSHIP": EmploymentType.FULL_TIME,
    "TEMPORARY": EmploymentType.FULL_TIME,
}
try:
    return EmploymentType(normalized)
except ValueError:
    return _EMPLOYMENT_TYPE_MAP.get(normalized, EmploymentType.FULL_TIME)
```
